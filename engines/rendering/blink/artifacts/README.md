# Nexus Blink Artifacts

This directory contains compiled artifacts produced from the Nexus Blink rendering engine.

Artifacts are generated by the Blink build system and should not normally be edited manually.

Supported artifact formats include:

- Linux shared libraries
- Windows dynamic libraries
- macOS dynamic libraries
- WebAssembly modules

Artifacts are separated by operating system and CPU architecture.

## Artifact Lifecycle

The normal artifact lifecycle is:

Source
→ Compile
→ Validate
→ Test
→ Sandbox
→ Sign
→ Stage
→ Approve
→ Load

Artifacts that fail validation or testing must not be promoted to a trusted engine state.

## Development Builds

Development builds may be replaced during live development.

The Nexus engine manager can use these artifacts for:

- Engine testing
- MicroVM testing
- Compatibility testing
- Performance benchmarking
- Hot reload
- Rollback

## Production Builds

Production artifacts should be:

- Reproducibly built
- Validated
- Tested
- Integrity checked
- Associated with an engine version
- Associated with a target platform
- Associated with a CPU architecture
- Verified before loading

Generated binaries should generally not be committed to the source repository unless the project specifically decides to distribute prebuilt artifacts.

## Directory Structure

- `linux/` contains Linux artifacts.
- `windows/` contains Windows artifacts.
- `macos/` contains macOS artifacts.
- `wasm/` contains WebAssembly artifacts.

Architecture-specific artifacts are stored beneath their operating-system directory.

## Security

An artifact must not automatically become a trusted Nexus engine simply because compilation succeeded.

The Nexus engine validation, trust, sandbox, health, and rollback systems remain responsible for determining whether an artifact can be loaded.

## Generated Files

The binary files in this directory are generated outputs.

Source code belongs in:

`../src/`

Public headers belong in:

`../include/`

Build configuration belongs in:

`../build/`
